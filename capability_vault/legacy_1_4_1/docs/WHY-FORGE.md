# Why Forge

A coding AI can inspect and repair a ZIP. That alone is not a reason to use Forge.

Forge exists because large AI-built projects lose continuity and justified confidence faster than they lose the ability to generate code.

## Project memory

Forge preserves the objective, accepted decisions, known defects, architecture, environment, source authority, and next action outside any one chat session.

## Cross-session continuation

Resume produces a bounded packet so a new AI or developer does not need to reread the entire project or rediscover old mistakes.

## Change control without Git

Forge compares deterministic per-file checkpoints and identifies added, modified, and removed paths between observations. This supports the existing folder and ZIP workflow while Git remains optional.

## Honest proof

Forge separates source validity, package integrity, entrypoint execution, prior-state upgrades, target-environment parity, delivery provenance, staging acceptance, and production observation. A green result at one level never silently implies the levels above it.

## Exact delivery

Ship is designed to produce the deployment ZIP, its hash, its included-file manifest, confidentiality result, strongest supported claim, blockers, and limitations as one release boundary.

## The promise

Forge should let humans and AIs work aggressively without losing project meaning, history, structure, or the difference between what passed and what was actually proven.
