# Forge Public Website Content Architecture

## Public location

- Parent brand: `https://emotivus.com`
- Forge product: `https://forge.emotivus.com`

## Primary categories

1. **Home** — Positioning, product value, current status, and the five-command system.
2. **Run Forge** — Exact first-target workflow, safe smart-start behavior, download, and expected output.
3. **Documentation** — Project Passport, Help, Adopt, Resume, Check, Ship, advanced systems, and current limitations.
4. **Roadmap** — Current development stage, planned releases, and ZIP-first product decisions.
5. **Trust** — Local-first operation, neutrality, model independence, confidentiality, scoped proof, and non-destructive startup.

Supporting pages:

- **Changelog** — Generated release changes.
- **Downloads** — Current `RUN-FORGE.zip`, release notes, and checksums.

## Content rules

- The first instruction is always **Run Forge.**
- The public command interface is always exactly **Help, Adopt, Resume, Check, Ship**.
- Advanced systems are documented but never dominate first contact.
- Development status and limitations must remain visible.
- Do not claim Forge is a coding model, commercial release, bug guarantee, automatic deployer, or sole production authority.
- Git is not required during the 1.x ZIP-first development cycle.

## Identity system

The official **Tempered Continuity** mark governs the full website:

- Open ring = work can resume.
- Ember/orange/gold = creation and active development.
- Blue endpoint = current verified handoff state.
- Cream typography = durable neutral product identity.
- Green = confirmed status only.

The ring may serve as wordmark O, favicon, launcher icon, status endpoint, and subtle interface motif. Avoid hammers, anvils, flames, robot faces, and generic code brackets.
