Commands

Help

Inspect minimal Forge state and recommend the exact next public command.

forge help --project .

Adopt

Create or refresh lightweight project understanding without advancing an existing observed checkpoint; explicitly record an exact-fingerprint authority baseline only as a separate reviewed operation.

forge adopt .

Resume

Generate layered continuation context with the exact next action plus compact authority-quarantine, evidence, identity, delivery, truth-state, and self-currency summaries.

forge resume .

Check

Reconcile canonical observed changes, expose authority quarantine separately, run only authorized verification, and evaluate current contracts and evidence.

forge check .

Forge notices

Every public command can return a structured ai_notice with a stable event ID, severity, summary, and whether it should be shown. Human output appends at most one concise Forge — … line when a meaningful new event occurs. Quiet mode limits notices to blockers, standard mode shows warnings and meaningful notices, and visible mode shows every structured notice. Repeated event IDs are suppressed.

Forge — Learned 3 new project facts.
Forge — Website checks passed; migration and deployment were not tested.

Truth states and verification tiers

Forge distinguishes OBSERVED, CONFIRMED, INFERRED, UNKNOWN, NOT_RUN, blocked-after-attempt, blocked-without-attempt, stale, and contradicted results. Evidence records static, sandbox, headless, emulator, device, staging, or production tier without implying broader coverage. Self-currency checks whether the objective source, Forge build, native-gate source, approval fingerprint, and retained evidence still describe the project. Resume keeps this compact and surfaces only actionable exceptions.

State integrity

Malformed Forge JSON blocks operation without being silently replaced by empty defaults. Valid JSONL records remain recoverable around damaged lines. Mutating commands use a project lock and an eight-file rollback transaction; critical writes flush and synchronize; supported state schemas migrate explicitly; new Ledger events are hash chained. These are local integrity controls, not cryptographic signatures or remote attestation.

Project identity

Adopt records an owner-controlled identity with an immutable build ID, optional release train, independently versioned components, contract versions, baseline, and monotonic platform identifiers. Forge never chooses or increments a product version. Absent components remain null, monotonic identifiers cannot decrease, and an optional exact-literal scan is restricted to project-owned paths and budgets.

forge adopt . --record-identity forge-project-identity.json

Resume carries only identity status, build ID, and component counts. Detailed component records stay local to conserve tokens.

Governed continuity register

Adopt can record one active project-owned continuity register with stable fact keys, explicit trust levels, exact support references, and known knowledge gaps. Owner-declared and project-evidenced records outrank developer, agent, and automatic records; lower-trust sources cannot silently replace them.

forge adopt . --record-continuity-register forge-continuity-register.json
forge resume .

Changed support becomes stale, open gaps remain visible until resolved or retired, and Resume exposes only compact current facts, gaps, and provenance references. Forge does not archive entire chats, use embeddings by default, authenticate the declarer, or turn remembered information into project authority.

Bounded session sidecar

Existing state.json carries an observational development, evidence-analysis, or release-assessment mode with current scope, authority status, mutation count, and latest Check or Ship state. It performs no background monitoring, model proxying, filesystem watching, or authority change.

Exact package families

Adopt can record a project-owned family that binds related ZIP artifacts to one active lineage, release version, and build ID. Declared outer bundles must contain the exact recorded child bytes. A changed-files package must name one exact parent and result, declare added, modified, deleted, and byte-preserving renamed paths, and reconstruct the exact result tree.

forge adopt . --record-package-family forge-package-family.json
forge check .

Forge verifies artifact identity and deterministic applicability. It does not execute the application, prove semantic merge correctness, or establish deployment safety.

Exact surface-to-evidence coverage

Adopt can bind routes, journeys, APIs, workers, installation, administrative, and other surfaces to one exact package-family result artifact. Exact entrypoints prove source presence only. Every higher tier requires an immutable scoped receipt, and a browser receipt does not silently prove database, authentication, device, staging, or production behavior.

forge adopt . --record-surface-coverage forge-surface-coverage.json
forge ship .

Forge reports PASS, FAIL, BLOCKED, STALE, and NOT_RUN per explicit tier. It does not drive the application, discover undeclared surfaces, establish reviewer competence, or decide whether project-required tiers are sufficient.

Authoritative exact-package release facts

Adopt can bind canonical release values to one active lineage, package family, and exact result artifact, then compare declared visible fields in packaged UTF-8 documents using exact prefix/suffix anchors and occurrence counts.

forge adopt . --record-release-facts forge-release-facts.json
forge ship .

Forge detects declared stale values, missing or duplicate anchors, forbidden legacy literals, package drift, and fact-source drift. It does not understand arbitrary prose or prove undeclared statements are current.

Active Ledger assertions

Project authority can record bounded deterministic predicates for decisions, resolved defects, guardrails, release rules, and project rules. Check re-evaluates active assertions and reopens a trusted claim when its current path, file, JSON, or ZIP predicate fails. Assertions cannot execute arbitrary commands, enter .forge, or prove semantic correctness.

forge adopt . --record-ledger-assertion ledger-assertion.json
forge check .

Full contracts and item results remain local. Resume exposes compact active, retired, and attention counts.

Check qualification

A green native result is not automatically a qualified detector. Forge records qualification only when the current check source is fingerprint-bound to authority-recorded known-bad cases it demonstrably rejected, along with tier, limitations, and scanned-surface count. Source or evidence drift makes qualification stale without rewriting the observed native result.

forge adopt . --record-check-qualification check-qualification.json
forge check . --run-native

Resume keeps negative-case detail local and reports compact qualified, unqualified, stale, and attention counts.

Safety guardrails

Atomic guardrails bind named surfaces into one required change set. Event obligations remain dormant until an authority-confirmed project event closes a temporary change window, then block until every declared obligation is addressed and an authority reviews the result. Path coverage never becomes feature-correctness proof.

forge adopt . --record-guardrail atomic-guardrail.json
forge adopt . --record-guardrail event-obligation.json
forge adopt . --confirm-project-event production-domain-confirmed   --project-event-evidence domain-confirmed.md   --project-event-authority owner
forge check .

Shared contract lifecycle

Project identity, native-gate approvals, capabilities, guardrails, and field trials share fingerprint-bound lifecycle meaning: proposed, active, approval-required, or retired. A missing or changed authority source cannot remain silently active.

Field validation

Adopt records a project-owned trial plan. A human reviewer or controlled fixture can link one observation to explicit Session Close. Forge aggregates only the local sample and does not grade itself, infer ground truth, establish causality, or claim universal product value.

forge adopt . --record-field-trial forge-field-trial.json
forge check . --close-session   --next-action "Run the next declared field scenario."   --field-observation field-observation-001.json

Ship

Assess a cumulative evidence ladder from observed checkpoint through explicit authority baseline, exact package, remote verification, Release Proof, and cold-session evidence while requiring every cumulative lower claim plus separate exact-package authorization before release-ready.

forge ship .

Bounded Ship claim ladder

Ship reports cumulative continuity-ready, checkpointed-candidate, authority-recorded-candidate, lineage-identified-candidate, migration-history-identified-candidate, package-family-identified-candidate, surface-coverage-mapped-candidate, native-verified-candidate, release-facts-current-candidate, runtime-content-verified, persisted-state-assured, final-package-bound, confidentiality-screened, public-release-reviewed, artifact-signature-verified, release-channel-bound, remote-channel-verified, release-proof-validated, cold-session-validated, owner-release-authorized, and release-ready levels. Each level requires every prior level. No lower claim invents public or production approval.

Detailed requirements stay in local structured evidence; human output shows the highest supported claim and unmet requirements.

Exact final-package certification

A project-owned release-package contract binds one exact ZIP to current owner identity and live artifact provenance, then performs a bounded archive scan and verifies project-owned public-review receipts against those same bytes.

forge adopt . --record-release-package forge-release-package.json
forge ship .

The bounded scan checks archive structure, sensitive live paths, private-key markers, non-placeholder secret assignments, and owner-declared contamination terms. Secret values and forbidden literal values are not retained in Forge state. A clean scan is not proof that every possible secret or confidential fact is absent.

Cross-Model Presentation Contract

A project-owned profile transfers audience layers, section order, verbosity, scoped PASS language, technical-detail placement, tables, bullets, and Forge-line behavior across AI models. Resume and the guided prompt carry one compact instruction; the full contract stays local.

forge adopt . --record-presentation-profile forge-presentation-profile.json

Forge transfers the communication system, not identical prose quality.

Signed Release Distribution

Forge verifies detached RSA PKCS#1 v1.5 SHA-256 signatures for the exact package and signed channel manifest using project-owned public keys only. Private keys remain external.

forge adopt . --record-release-distribution forge-release-distribution.json
forge ship .

Project-owned publication receipts must match the signed manifest and exact package. An authority-approved remote-verification block may then let explicit Ship freshly stream each required HTTPS artifact, compare exact byte length and SHA-256, and discard the response body. A PASS does not prove future availability or continuous CDN integrity.

Matched Cold-Session Evidence

Schema-2 campaigns bind human-reviewed fresh-agent Forge/control pairs to one exact Forge runtime and one exact host package, shared immutable task and baseline artifacts, provider/model settings, isolated sessions, current evidence, correction counts, time, and optional exact tokens. Controlled fixtures remain diagnostic and do not count toward real coverage.

forge adopt . --record-cold-session-validation forge-cold-session-validation.json
forge ship .

A PASS is bounded local-sample evidence, not universal causal proof or commercial validation.

Advanced capability activation

Recommendations never activate capability. Forge Doctor runs only after Adopt validates a project-owned contract containing real trigger evidence, scope, exclusions, budgets, focused regressions, authority, distinct native value, and an explicit no-repair rule.

forge adopt . --activate-capability doctor --capability-contract forge-doctor-contract.json
forge check . --run-capability doctor

Contract changes require explicit reactivation. Doctor is diagnose-only and does not prove production equivalence.

Content-aware Runtime Proof

Runtime Proof is a separate clean-room, contract-gated HTTP capability. Recipes require exact origins, status, content type, minimum bytes, required markers, forbidden markers, timeout, response budget, tier, and exclusions. Status-only liveness is invalid; response bodies are discarded.

forge adopt . --activate-capability runtime-proof --capability-contract forge-runtime-proof-contract.json
forge check . --run-capability runtime-proof

It does not execute JavaScript, inspect layout, authenticate, prove database state, or establish release readiness.

Runtime State and Deployment Matrix

Project-owned scenarios bind exact candidate identity fields, baseline, target environment, deployment stage, prior persisted-state identity, migration-file digests, allowed evidence authority, and same-Check Runtime Proof recipes. Missing evidence remains NOT_RUN; disagreement blocks Check.

forge adopt . --record-runtime-matrix runtime-state-matrix.json
forge check . --run-capability runtime-proof --runtime-state-evidence runtime-state-evidence.json

Forge does not deploy, restore persisted state, execute migrations, inspect data correctness, prove rollback, or certify release readiness. Detailed bindings stay local to conserve tokens.

Persisted-State Coverage and Semantic Validation

Project-owned transition plans can use exact, semantic, or combined JSON snapshot checks; declare all or any coverage across state paths; bind exact artifact and migration bytes; and require same-Check Runtime Proof. Rollback availability, an executed drill, and restored-state correctness remain separate results.

forge adopt . --record-state-transition state-transition-plan.json
forge check . --run-capability runtime-proof   --state-transition-evidence state-transition-evidence.json

Missing evidence remains NOT_RUN; mixed matrices remain PARTIAL. Semantic checks use a bounded deterministic JSON vocabulary—including allowed array values and cross-collection reference integrity—and a 2 MB snapshot budget. Forge does not deploy, migrate, restore, roll back, connect to a database, run arbitrary validation code, inspect hidden data, or certify release readiness. Snapshot contents and detailed receipts remain local to conserve tokens.

Bounded Release Proof

After one exact final package is current, Adopt can record a project-owned assurance map covering exact ZIP surfaces and all nine release domains. Required obligations use current package-bound receipts; not-applicable domains need an explicit rationale.

forge adopt . --record-release-proof forge-release-proof.json
forge ship .

A PASS can support release-proof-validated. Forge does not execute the underlying reviews, discover undeclared surfaces, establish reviewer competence, validate arbitrary methodology, or authorize release.

Exact-Package Release Authorization

After the exact package and lower evidence layers are current, Adopt can record one separate project-owned authorization for that package and named channels. The source, digest, byte length, build, decision, rationale, conditions, and expiration are checked again during Ship.

forge adopt . --record-release-authorization forge-release-authorization.json
forge ship .

A PASS can support owner-release-authorized. Forge validates the project record but does not authenticate the declaring person, establish legal authority, prove universal correctness, or guarantee future channel state.

Capability vault

The development package preserves legacy Doctor, Graph, Lab, Evidence, runtime/release-proof research, confidentiality, CI, Update, Mirror, and legacy memory references. Active Doctor, Runtime Proof, and Release Proof implementations are clean-room controlled-core code and do not import the legacy vault. The public runtime excludes the vault.

Decision forks

Resume detects bounded representation conflicts before implementation. Adopt records the owner-authorized option, rejected alternatives, rationale, authority, and evidence in the Ledger. Later Resume packets preserve the same model-neutral governing context.

Observed Check and explicit authority

Observed-checkpoint reconciliation is the canonical changed-path source, not project-authority acceptance. Adopt refreshes preserve the checkpoint. Check prints the exact review fingerprint, and a separate exact-fingerprint Adopt operation records authority. Unexpected mutations remain quarantined from authority-bound Ship claims until explicitly reviewed and reauthorized.

forge check .
forge adopt . --authorize-baseline <snapshot-sha256> --baseline-reason "Reviewed exact tree."
forge check . --checkpoint

Deployable boundaries

Project-owned roles classify the canonical observed changed set. Overlaps block, strict contracts reject unclassified paths, and registered delta ZIPs can be checked against allowed changed paths and the owner-declared baseline.

Canonical claims

Explicit owner-facing statements can be checked against current identity, registered ZIP membership, migration effects, and evidence identity. Forge does not infer arbitrary prose meaning.

Confirmed relationships

Project-owned relationship sets connect canonical observed changed paths with confirmed entry points, includes, imports, behavior bindings, resource consumers, decisions, migrations, and tests. Related paths remain impact context rather than manufactured changes, and detailed maps stay local for token conservation.

forge adopt . --record-relationship-set forge-relationships.json

Objective recovery

Redirect-only and truncated fragments are rejected. Forge can follow an explicit project-local authority link to the first unfinished ordered item while retaining the rejected fragment as local evidence.

Native execution authority

Canonical gates are Forge-authorized, owner-only, external-CI, or evidence-import-only. Only the first mode permits explicit Forge execution. Matching owner or CI evidence can be imported without being relabeled as Forge execution.

Exact native invocation

Forge-authorized execution is bound to exact argv, project-relative working directory, bounded non-secret environment, timeout, verification tier, and expected coverage. A zero-exit run with missing approved gate members fails.

Portable continuity companion

Session Close can export the eight Forge state files and bounded structured evidence as a separate private ZIP, optionally bound to the exact development package. Project source, deployable files, raw logs, response bodies, and credentials are excluded.

forge adopt . --native-mode owner-only
forge check . --import-native-evidence native-evidence.json

Telemetry boundary

Forge separates observed local facts, exact provider reports supplied by the operator, and heuristic estimates. Resume reports overhead and reuse conservatively. At least three matched exact-provider pairs are required before an in-sample break-even finding; no workspace-byte or character estimate becomes an actual savings claim.

forge check . --close-session --next-action "Continue"   --provider "Example Provider"   --provider-input-tokens 1200   --provider-output-tokens 300   --retry-count 1 --correction-count 0   --benchmark-id task-01 --benchmark-arm with-forge
