The reset

Authority before inference. Capability only when earned.

The controlled core separates lightweight continuity from the frozen 1.4.1 capability vault.

01

Progressive understanding

Forge records observed, inferred, confirmed, contradicted, and stale knowledge instead of manufacturing certainty on first contact.

02

Native tools first

Forge detects the canonical quality runner, records whether Forge, the owner, or CI may execute it, and never bypasses that authority.

03

Visible and actionable

One concise Forge — … notice reports what happened, while one bounded Forge recommends this prompt — … line tells a non-technical user what to ask the AI to do next.

Small public interface

Run Forge now performs a bounded active intelligence pass, then becomes a passive sidecar.

Advanced systems are preserved, inactive, and governed by activation contracts rather than hidden startup imports.

01

Help

Inspect minimal Forge state and recommend the exact next public command.

forge help --project .
02

Adopt

Create or refresh lightweight project understanding without advancing an existing observed checkpoint; explicitly record an exact-fingerprint authority baseline only as a separate reviewed operation.

forge adopt .
03

Resume

Generate layered continuation context with the exact next action plus compact authority-quarantine, evidence, identity, delivery, truth-state, and self-currency summaries.

forge resume .
04

Check

Reconcile canonical observed changes, expose authority quarantine separately, run only authorized verification, and evaluate current contracts and evidence.

forge check .
05

Ship

Assess a cumulative evidence ladder from observed checkpoint through explicit authority baseline, exact package, remote verification, Release Proof, and cold-session evidence while requiring every cumulative lower claim plus separate exact-package authorization before release-ready.

forge ship .

Current boundary

Useful continuity without false release confidence.

Ship can report a bounded release-ready PASS only when every cumulative project-declared requirement and a separate exact-package authorization are current.
