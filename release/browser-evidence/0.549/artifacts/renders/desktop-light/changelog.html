Changelog

0.549 · Authority-Gated Aggregate Check Truth

Forge now refuses to report project-level PASS on an unbaselined tree: clean observed checks remain available, but the aggregate is NOT_RUN until an exact reviewed fingerprint is authorized; real defects still fail immediately.

Current build highlights

  • Changed clean unbaselined Scoped Check results from aggregate PASS to NOT_RUN while preserving component observations.
  • Added explicit aggregate eligibility, reason, resolving state artifact, and an exact authority-then-checkpoint command.
  • Preserved immediate FAIL for real blockers and native verification failures before baseline authority exists.
  • Prevented unbaselined NOT_RUN results from creating checkpoints or satisfying Ship last-check-pass prerequisites.
  • Updated portable writer trials and integrity campaigns to prove NOT_RUN → exact authority → PASS checkpoint → DRIFTED refusal.
  • Added five focused regressions for aggregate truth and migrated legacy workflows to establish authority only where checkpoint truth is required.
  • Re-verified the owner-supplied final recommendation claim by claim; disproved three major status claims and did not adopt unsupported wholesale deletions.
  • Kept roadmap percentages explicitly limited to implementation/instrument coverage rather than defect-catching efficacy.
  • Expanded focused public-neutral regressions from 510 to 515 across 53 isolated modules.
  • Advanced the seven-axis implementation roadmap to 90 / 98 / 97 / 88 / 99 / 63 / 88 — 623 / 7 = 89.0%, reported as 89%.

Current certification

Focused neutral regressions cover the active core, including governed trust-ranked continuity facts, explicit knowledge gaps, bounded sidecar state, observed-checkpoint preservation, explicit authority baselines, exact project lineage, migration semantic identity, exact package families, outer-bundle member identity, deterministic changed-files applicability, exact surface-to-evidence coverage, authoritative exact-package release facts, stale visible-value detection, collision detection, and mutation quarantine. Runtime-state and state-transition scenarios remain bounded testimony checks. Ship now binds one exact ZIP to live provenance, performs bounded confidentiality screening, verifies package-bound public reviews, verifies detached package and channel-manifest signatures, binds signed channel metadata to publication receipts, freshly verifies exact remote artifact bytes through authority-bounded HTTPS retrieval, validates project-declared exact-package Release Proof obligations, and assesses schema-2 human-reviewed matched cold-session evidence with exact runtime, host-package, task, baseline, isolation, and age controls. A separate exact-package authorization now precedes bounded release-ready. Forge does not authenticate the declaring person and does not perform deployment, migration, restoration, rollback, database access, private-key operations, or arbitrary semantic validation; hidden-data correctness, browser layout, exhaustive confidentiality proof, universal causal efficacy, and commercial readiness remain excluded.
