Trust and boundaries

Preserve project truth without importing private projects into Forge.

Forge is local-first, model-independent, public-neutral, and explicit about what each result proves.

LOCAL-FIRST

Project state stays local

Forge writes the eight-file continuity state beside the project. It does not require a hosted Forge service.

VISIBLE RESTRAINT

Forge speaks only when useful

One structured notice reports meaningful activity; one separate copy-ready prompt tells the user what to do next without copying detailed evidence into chat.

STATE INTEGRITY

Damage blocks instead of disappearing

Strict reads, schema migration, locking, rollback, durable writes, and Ledger hash chaining protect local continuity state while avoiding cryptographic-signature claims.

PUBLIC-NEUTRAL

No private project material in Forge

Source, tests, examples, and releases use neutral synthetic fixtures or properly licensed public projects.

COLD VAULT

Legacy capability is inactive

The audited 1.4.1 source is preserved in the development package but excluded from ordinary imports, scans, Resume packets, and the public runtime package.

OWNER IDENTITY

One identity, multiple components

The owner records build, release-train, component, contract, baseline, and monotonic identities. Forge rejects rollback but never assigns a project version.

EXPIRING SAFETY

Temporary permission can close

Event obligations stay dormant until an authority-confirmed project event closes the free-change window, then remain blocked until the declared work is reviewed.

ATOMIC SAFETY

Unsafe fragments stay blocked

Authority-recorded guardrails bind required project surfaces into one change set while refusing to equate coverage with correctness.

SHARED LIFECYCLE

Changed contracts lose approval

Identity, native gates, capabilities, guardrails, and trials share fingerprint-bound proposed, active, approval-required, and retired states.

ACTIVE LEDGER

Trusted claims are rechecked

Authority-recorded deterministic obligations reopen a resolved claim when its current project state contradicts the recorded predicate.

QUALIFIED CHECKS

Green is not capability proof

Native results stay separate from evidence that the current detector rejected declared known-bad cases. Changed source or evidence makes qualification stale.

ARTIFACT LINEAGE

Evidence is not provenance

Registered artifact bytes are checked against exact input, generator-source, and baseline digests. Unregistered deliverables remain visibly outside the assurance perimeter.

AUTHORITY BASELINE

Observed bytes are not approval

Adopt refreshes preserve the observed checkpoint. Exact-fingerprint authority is recorded separately; later mutations remain quarantined. Forge does not authenticate identity or prove authorship.

MIGRATION IDENTITY

A sequence number is not a body

Exact lineage catalogs bind sequence, semantic ID, path, and body digest. Number-only ledgers remain unknown, and cross-lineage collisions require append-after-highest reconciliation.

PACKAGE FAMILY

A filename is not applicability

Related archives bind to one lineage and exact bytes. Outer bundles must contain the declared children, and changed-files packages must reconstruct the exact result tree from one exact parent.

SURFACE EVIDENCE

A route map is not a tested journey

Exact package entrypoints and user-flow steps stay separate from database, authenticated, browser, device, staging, and production receipts. Higher tiers never silently fill other tiers.

DELIVERY ROLES

Changed is not automatically shippable

Project-owned boundaries classify changed paths and can bind registered deltas to allowed roles and the real baseline.

CANONICAL CLAIMS

Owner-facing truth is checkable

Explicit identity, package, migration, and evidence claims are rechecked without pretending Forge understands arbitrary prose.

RELEASE FACTS

Visible package text must stay current

Declared version, schema, package, surface, native, and literal values are extracted from exact packaged documents. Unscanned prose remains outside the claim.

OBJECTIVE AUTHORITY

Fragments are not work

Redirect-only and truncated objective candidates are rejected; explicit project-local authority links may recover the first unfinished ordered item.

NATIVE AUTHORITY

Execution belongs to the project

Forge-authorized, owner-only, external-CI, and evidence-import-only modes preserve who may execute the canonical gate and who produced imported evidence.

EXACT INVOCATION

A script fingerprint is not enough

Authority binds the exact arguments, working directory, bounded environment, timeout, tier, and expected gate members. Partial execution cannot appear complete.

GOVERNED CONTINUITY

Remembered facts retain trust and support

Stable fact keys, explicit gaps, support references, supersession, and stale-evidence checks preserve current project truth without making automatic memory authoritative.

BOUNDED SIDECAR

Aware without becoming autonomous

The sidecar records mode, scope, authority state, mutations, Check, and Ship status. It does not monitor chat, proxy model traffic, or change the project in the background.

PORTABLE HANDOFF

Continuity stays separate from deployment

A private companion ZIP carries eight state files and bounded result manifests, may bind to the exact development package, and excludes raw logs and project source.

CONFIRMED LINKS

Impact expands without fake changes

Project-owned relationships connect entry points, includes, behavior, resources, decisions, migrations, and tests while keeping related paths distinct from files that actually changed.

CONTRACT-GATED

Doctor is earned, not assumed

A project-owned contract, real trigger evidence, exact scope, budgets, and focused regressions are required. Doctor cannot repair or claim production equivalence.

RUNTIME CONTENT

HTTP 200 is not enough

Exact-origin GET recipes require minimum bytes, expected content type, required markers, and forbidden-error checks. Bodies are discarded and browser behavior remains unproven.

RUNTIME STATE

Evidence stays candidate-bound

Owner or CI testimony must match the exact candidate, baseline, prior-state identity, migration bytes, target stage, and same-Check runtime recipes. Forge does not perform those operations.

STATE COVERAGE

Untested combinations stay visible

Exact or bounded semantic JSON snapshots, explicit coverage groups, artifact and migration bytes, receipts, and rollback levels stay distinct. Forge verifies testimony but performs none of the operations.

FINAL PACKAGE

One exact ZIP, not a release label

Current package bytes must match owner identity and live artifact provenance, including current inputs, generator source, and declared baseline.

CONFIDENTIALITY SCREEN

Bounded, local, and value-minimizing

Forge checks archive structure, sensitive paths, private-key markers, non-placeholder secret assignments, and owner-declared contamination terms without retaining the private values.

PUBLIC REVIEWS

Review receipts follow the exact package

Security, privacy, accessibility, compatibility, installation, upgrade, and rollback receipts must bind to the same package digest and current candidate identity.

REMOTE RELEASE

Fresh bytes, bounded meaning

Explicit Ship may retrieve credential-free HTTPS artifacts only from authority-approved origins, compare exact bytes, and retain no response body. Future availability remains unproven.

RELEASE PROOF

Declared surfaces need current receipts

All nine domains are explicitly classified. Required obligations bind exact ZIP surfaces to package identity, validity, reviewer requirements, evidence tier, scope, and immutable evidence artifacts.

RELEASE AUTHORIZATION

Exact package, explicit channels

A separate expiring project-owned contract binds the exact package digest, byte length, build, authority source, decision, rationale, conditions, and named channels. Forge validates continuity but not human identity or legal power.

SHIP LADDER

No lower claim invents authority

Continuity through authority-recorded project state, remote-channel verification, Release Proof, cold-session evidence, and exact-package authorization is assessed cumulatively. Release-ready can pass only when the entire bounded ladder is current.

EXACT CLAIMS

Unknown remains unknown

Unrun checks remain NOT_RUN; blockers say whether execution was attempted; static, sandbox, device, staging, and production evidence retain distinct tiers.

SELF-CURRENCY

Forge checks its own memory

Objective sources, native-gate paths, approval fingerprints, Forge version, and evidence freshness are rechecked against the current project before their records are trusted.

MEASURED EFFICIENCY

Heuristics stay labeled

Provider reports, observed local facts, and estimates are separate. Matched benchmark results remain limited to the measured sample.

NO SELF-GRADING

Field evidence stays human-grounded

Forge validates field observations, but controlled fixtures cannot satisfy real cold-session release coverage. Forge cannot authenticate reviewers, establish ground truth, causality, universality, or commercial value.

Smart-start boundary

Run Forge is intentionally non-destructive.

It may orient, resume, or run changed-file core checks. Higher-risk actions remain explicit.
