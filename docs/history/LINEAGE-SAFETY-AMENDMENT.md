## Confirmed product lessons

1. A display version is not an immutable project identity.
2. A continuation or delta must identify its exact parent package and tree.
3. An incoming branch from another parent must remain a merge candidate.
4. Migration sequence numbers need semantic identity and body hashes.
5. Changed-files packages need applicability proof and a reconstructed-tree identity.
6. Verified inner artifacts do not authenticate a later outer repackaging.
7. A route map is a declared surface inventory, not browser or device proof.
8. Authority-looking documents need an explicit precedence hierarchy and generated repeated facts.
9. Packaged native gates must prove their own compatibility dependencies are present.
10. Field failures should become neutral fixtures only after proprietary details are removed.

## Planning decision

The next implementation work should prioritize lineage-safe continuation before additional real matched cold-session campaigns. Cold-session evidence remains valuable, but it should not count when both arms cannot be proven to start from one exact parent lineage.
