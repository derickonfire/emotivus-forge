# Minimal State Schema

A fresh adoption creates eight files under `.forge/`:

1. `passport.json` — identity, scope, evidence, lineage, package, surface, continuity, and third-party-intake summaries;
2. `resume.md` — bounded owner, builder, expert, retrieval, progress, and efficiency continuation packet;
3. `ledger.jsonl` — append-only hash-chained authority and project events;
4. `authorities.json` — ranked authority candidates and confirmations;
5. `native-tools.json` — schema-4 canonical quality ecosystem and exact invocation records;
6. `settings.json` — schema-21 bounded settings and project-owned contracts;
7. `state.json` — schema-4 observed checkpoint, authority baseline, sidecar, change/truth summary, and latest operations;
8. `metrics.jsonl` — truth-labeled local telemetry and optional exact provider reports.

Evidence directories are created only by explicit evidence-producing operations and are excluded from the eight-file count. Malformed state is preserved and blocks mutation.

## Core state schema 4

Core state schema 4 preserves separate observed and authority baselines and adds the compact non-authoritative session sidecar. It performs no background monitoring and grants no authority.

## Settings schema 21

Settings schema 21 preserves all schema-20 contracts and adds one `session_adapters` block, off by default:

- `third_party_intakes` — active, retired, and historical exact upstream intake records;
- `third_party_control_paths` — exact intake contracts excluded as control metadata while cited project support remains inside lineage identity.

Each intake may bind an external archive, exact reviewed members, license, attribution, dependencies, adaptation classification, behavior changes, security review, tests, distribution boundary, update process, and retirement. The full upstream archive remains outside `.forge` and outside public packages.

Schema 19 added governed continuity and the session sidecar. Schema 18 added exact-package release facts. Schemas 14–17 added lineage, migration identity, package families, and surface evidence.

Detailed source archives, conversation history, response bodies, credentials, identity proof, migration bodies, and review bodies remain outside `.forge`. No ninth top-level state file is added.
