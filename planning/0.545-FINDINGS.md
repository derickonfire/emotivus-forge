# Forge 0.545 findings register

Status: closed. Five findings recorded before correction; five dispositioned; zero open. Never rewrite a sealed prior build.

## F-545-001 — External evidence protocols lack one portable exact-runtime execution kit

The 0.544 roadmap correctly requires independent multi-writer evidence and a matched handoff benchmark, but the development and public packages provide separate documentation, an integrity campaign tool, and an in-memory benchmark instrument rather than one deterministic package bound to the exact public runtime. An operator must manually assemble files and can accidentally test different bytes.

## F-545-002 — The multi-writer campaign cannot preserve a manual controller/writer handoff

`tools/run_integrity_campaign.py` creates a separate writer process, but the controller launches it itself. That is valid local synthetic evidence and is truthfully labeled, but it does not provide a two-step protocol that a separately controlled operator can execute on another machine or filesystem while retaining a challenge, before/after hashes, process metadata, and the exact Forge result.

## F-545-003 — The matched benchmark has no sealed packet lifecycle

`emotivus_forge.core.continuity_benchmark` correctly rejects estimates, unmatched arms, shared workspaces, and missing human acceptance. It intentionally persists nothing. The distribution lacks a packet generator that binds the task, exact runtime digest, provider/model, distinct arm workspaces, fillable run templates, and final comparison validation without turning a template into evidence.


## F-545-004 — Portable writer preparation supplied a non-path objective source

The first extracted-kit execution reached Forge Adopt and failed because the runner supplied `portable-evidence-kit` as `--objective-source`. Forge correctly requires an existing project-owned source path. The neutral trial already creates `BACKLOG.md`, so the protocol must bind the confirmed objective to that exact file rather than adding a special-case authority bypass.

## F-545-005 — Benchmark validation errors escaped the standalone JSON boundary

The focused kit regression confirmed that null token templates are rejected by `continuity_benchmark.record_run`, but the runtime-defined `BenchmarkError` is a separate `ValueError` class from the runner's `RunnerError`. It escaped `main()`, produced a traceback on stderr, and left stdout empty. The runner must preserve the refusal while returning one structured FAIL object to operators and automation.
