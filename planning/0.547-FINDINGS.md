Status: CLOSED. Fifteen findings were recorded before correction or disposition; thirteen were corrected; two outer execution-cutoff incidents were disproved by bounded reruns; zero remain open. Never rewrite sealed 0.546 artifacts.

## Authorized objective

The owner directed Forge development to continue after sealed 0.546. The next legitimate in-container slice is **portable return-evidence intake and bounded adjudication**: validate exact returned attestation, independent-writer, and matched-handoff receipts against their sealed kits; reject contamination, tampering, duplicate/replayed submissions, and overclaiming; emit one content-addressed review receipt; and preserve false release authorization plus every external `NOT_RUN` boundary.

## F-547-001 — Returned evidence has no source-owned intake boundary

The 0.546 standalone runners can verify their own local output, but Forge source has no unified command that accepts a returned ceremony or evidence result and independently adjudicates it against the original sealed kit. Review therefore depends on manually replaying workflow-specific commands.

## F-547-002 — No portable return-bundle schema binds operator output to its sealed kit

Attestation ceremony output, writer protocol output, and matched benchmark output are directories with different layouts. There is no deterministic return archive with an exact kit ID, workflow kind, payload inventory, and content identity suitable for transfer to another reviewer.

## F-547-003 — Duplicate and replayed submissions have no stable review lifecycle

Receipts have local IDs, but Forge does not produce a cross-workflow submission ID or compare it with prior adjudication receipts. The same exact return can be presented repeatedly without a first-seen/duplicate classification.

## F-547-004 — Workflow-specific PASS text can be overread as authority or independence

A valid detached signature proves a key verified exact bytes; a reviewed writer candidate proves a local detector result; and a paired benchmark proves one exact sample. Forge has no normalized review result that carries these different claim scopes and explicitly preserves unauthenticated identity, unproven administrative independence, false release authorization, and non-generalization.

## F-547-005 — Returned evidence is not screened as an inbound confidentiality boundary

The kits contain no private key, but a returned operator directory or archive could accidentally include private-key material, credentials, unrelated files, or undeclared payloads. Forge has no allowlisted inbound bundle boundary that blocks such contamination before review.

## F-547-006 — No immutable adjudication receipt binds review result to exact inputs

There is no content-addressed Forge review receipt binding the sealed kit, returned payloads, verification result, exclusions, reviewer assertion, and prior-receipt comparison. A copied review summary can become detached from the files it described.

## F-547-007 — Inbound private-key markers matched their own detector source

The first focused package build reported three `private-key-block` BLOCK findings in the new reviewer and standalone runners because the detector source contained complete PEM private-key headers as literals. The rule is valid, but its representation must not contaminate Forge’s own distributable source.

## F-547-008 — Portable and core public-key fingerprints use different canonical bytes

Cross-review of a valid 0.546 ceremony showed that `portable_attestation_runner.py` hashes canonical public-key JSON with a trailing newline while `release_distribution.py` hashes the same canonical JSON without one. The same exact public key therefore has two Forge fingerprints. Sealed 0.546 receipts require compatibility, but new ceremonies must converge on the core canonical fingerprint.

## F-547-009 — Canonical product roadmap still labeled implemented screening as the next focus

though that capability was implemented and certified in 0.542. The stale stage label could misdirect a
new session away from the current owner-authorized objective. Correct the canonical row to completed
without rewriting historical release records.
