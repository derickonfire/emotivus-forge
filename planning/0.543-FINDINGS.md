# Forge 0.543 findings register

Status: **CLOSED certification record — 18 findings recorded before correction, 18 corrected, 0 open.**

## F-543-001 — no native pre-seal workspace drift refusal

The 0.542 core had an operation lock for concurrent Forge writes and observed snapshots for
change detection, but it did not content-fingerprint an exact seal candidate and refuse Ship
when project bytes changed after that checkpoint. External writers were therefore outside the
native seal boundary.

## F-543-002 — no undeclared artifact collision observer

Lineage contracts rejected same-version/different-tree declarations unless explicitly resolved,
but Forge did not scan ordinary observed ZIP artifacts for the same artifact identity and version
with different exact bytes. A rival package could therefore remain outside lineage controls.

## F-543-003 — package builder did not prove source selection stayed stable during build

The deterministic package builder selected source paths and wrote them into a ZIP, but it did not
bind every read to a pre-build content digest and recheck the selected source set before publishing
the output. Deterministic timestamps do not detect a concurrent content writer.

## F-543-004 — certification guarded roadmap arithmetic more strongly than narrative structure

`tools/check_progress_status.py` checked canonical roadmap rows and percentages, but certification
did not natively validate the broader version, regression-count, state-schema, required-path, and
website-download narrative relationships that the outer continuity verifier checked.

## F-543-005 — public README regression count was stale inside the 0.542 source tree

`README.md` still reported 372 regressions across 41 modules while the sealed 0.542 certification
recorded 444 regressions across 44 modules. The stale text did not affect the sealed certification
record, but it demonstrates the broader narrative-structure gap this cycle is intended to close.

## F-543-006 — initial narrative checker read the wrong manifest field and compared raw path patterns

The first implementation read `FORGE-MANIFEST.state`, which is the distribution lifecycle label,
instead of `FORGE-MANIFEST.state_schema`. It also required every raw `public_paths` pattern to
appear literally in `canonical_paths`, even when a public file was already covered by a canonical
directory pattern. Both checks produced false findings and were corrected before certification.

## F-543-007 — first build-attestation implementation depended on private helper names

The initial attestation verifier imported underscored RSA key and detached-signature readers
from `release_distribution.py`. The cryptographic primitive was correctly reused, but binding a
new public capability to private helper names created an unnecessary maintenance hazard. Public
read-only wrappers were added before certification; no second cryptographic implementation was
introduced.

## F-543-008 — package-builder setup did not classify selection validation errors uniformly

The package builder's pre-build setup caught manifest and runtime errors but did not include
`ValueError`, even though content-selection validation may raise it. That could escape the
standard `FORGE PACKAGE: BLOCKED` boundary instead of producing a controlled refusal. The setup
boundary was expanded before certification.

## F-543-009 — schema migration regression retained the former terminal schema literal

After core state advanced from schema 4 to 5, the authority-baseline migration regression still
asserted that a schema-2 fixture must terminate at schema 4. Runtime migration correctly produced
schema 5; the test encoded the former current version instead of the runtime constant. The stale
expectation was recorded before correction and changed to assert `CORE_STATE_SCHEMA`.

## F-543-010 — second legacy migration regression retained the former core schema literal

The notices and integrity migration test also hardcoded schema 4 as the terminal state. Runtime
correctly migrated the schema-1 fixture through every step to current schema 5. The stale literal
was recorded before correction and replaced with `CORE_STATE_SCHEMA`.

## F-543-011 — progress regression hardcoded the previous rounded overall percentage

The progress-consistency regression expected 87 even after the owner-authorized re-scope produced
603 / 7 = 86.1, reported as 86. The checker correctly returned 86. The test was corrected to derive
the expected value from canonical `FORGE-PRODUCT.json` rather than freezing a prior roadmap result.

## F-543-012 — progress regression also hardcoded the previous axis vector

After the rounded percentage assertion was corrected, the same regression still froze the former
90 / 100 / 96 / 88 / 99 / 58 / 76 vector. The runtime checker correctly returned the newly
owner-authorized 90 / 96 / 96 / 88 / 99 / 58 / 76 vector. The expectation was recorded before
correction and changed to derive every axis from canonical product metadata.

## F-543-013 — isolated-runner unit fixture omitted the new narrative-certification stage

The self-test runner regression mocked isolated module execution but supplied a synthetic root with
no Forge narrative surfaces. After narrative integrity became part of successful self-test, the
fixture returned failure even though the behavior under test was module aggregation. The test was
recorded before correction and now mocks a scoped narrative PASS while retaining separate native
narrative-integrity tests.

## F-543-014 — session-adapter schema invariant froze the former core-state version

The session-adapter invariant correctly held settings at schema 21 but also hardcoded core state 4.
Core state advanced to 5 for workspace-integrity data inside existing `state.json`; adapter behavior
and the eight-file boundary did not change. The stale literal was recorded before correction and
updated to schema 5.

## F-543-015 — first narrative gate required development-only surfaces in the public edition

The initial native narrative checker always opened `CERTIFICATION.md`,
`IMPLEMENTATION-REPORT.md`, and `docs-site/downloads`, although the declared public edition
intentionally excludes those development and generated-website surfaces. Public self-test would
therefore fail or raise after its regression modules passed. The edition-boundary defect was
recorded before correction. Public narrative certification now derives counts from its packaged
manifest and checks only public surfaces; development/source certification retains the fuller
certification, implementation, and website-download relationships.

## F-543-016 — narrative relationships did not bind to the self-test's observed count

The narrative checker synchronized manifest, README, certification, and website declarations, but
its first self-test integration did not pass the actual module and regression totals into that
check. All documents could therefore agree on one stale number while the runner observed another.
The gap was recorded before correction. The self-test now supplies its observed totals and
narrative integrity fails when either differs from certified metadata.

### F-543-017 — isolated self-test aggregate can stall between passing modules

- **Observed before correction:** `python3 -u forge.py self-test` reported modules 1–26 as PASS, then exceeded a 300-second outer bound before reporting module 27. `tests.test_relationships`, the next sorted module, passed alone in about one second.
- **Risk:** a correct module result can be masked by runner process-lifecycle behavior, preventing bounded certification and confusing a test timeout with a product regression.
- **Required correction:** isolate and bound the runner cleanup/wait primitive itself; preserve truthful per-module results and terminate descendants without allowing cleanup to stall the aggregate command.

**Reproduction and disposition:** The same three-module runner primitive completed normally, and a fresh full aggregate run then completed all 47 modules with 475/475 PASS and narrative integrity PASS. Plain discovery also completed 475/475 with exit code 0. No deterministic Forge runner defect was reproduced, so no speculative source change was made. The failed attempt is retained as an outer-execution timeout observation; certification relies only on the later clean bounded executions.

## F-543-018 — two narrative regressions assumed development-only files in the public edition

The first four-surface certification run found that runtime narrative integrity passed in the public package, but two unit fixtures errored before reaching assertions: one unconditionally opened `docs-site/downloads/RELEASE-NOTES.md`, and one unconditionally removed `docs-site`, `CERTIFICATION.md`, and `IMPLEMENTATION-REPORT.md`. Those surfaces are intentionally absent from the public edition. The defect was recorded before correction. The fixtures must remain meaningful in both editions: development verifies checksum drift is rejected, while public verifies development-only website evidence is outside its declared boundary; cleanup uses missing-safe operations.

**Finding reopened before correction:** A later final-source certification attempt stalled again, this time after module 23, and exceeded a 600-second outer bound without a module failure. This disproved the earlier non-reproduction disposition. The child unittest runner is therefore being corrected to terminate itself with `os._exit` immediately after flushing the completed result, bypassing lingering non-daemon interpreter state, while the parent retains bounded process-group cleanup and no unbounded post-timeout wait.

## Certification closure

F-543-017 was corrected with an explicit child unittest result boundary and bounded process-group cleanup. Its synthetic lingering-thread proof returns the completed result without waiting for interpreter shutdown. F-543-018 was corrected with edition-aware fixtures and passed on source, public, development, and website-embedded surfaces. All 18 findings are closed; no open finding was waived or omitted.
