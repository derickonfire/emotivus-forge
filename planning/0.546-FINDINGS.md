# Forge 0.546 findings register

Status: CLOSED. Eight findings were recorded before correction; eight were corrected; zero remain open. Never rewrite sealed 0.545 artifacts.

## F-546-001 — Exact-package build attestation has no portable ceremony lifecycle

Forge can emit a deterministic build manifest and verify a supplied public key plus detached signature, but an external operator must manually assemble the package, manifest, verifier, instructions, and result. There is no exact-runtime-bound deterministic ceremony kit and no explicit `NOT_RUN` request state.

## F-546-002 — The declared packaged Forge-manifest digest is not reverified

`build_manifest_payload()` records `forge_manifest_sha256`, but `verify_build_attestation()` does not extract the unique packaged `FORGE-MANIFEST.json` member and compare its exact bytes to that digest. A signed build manifest therefore contains one identity field that the verifier currently reports without proving.

## F-546-003 — Owner-key identity is not precommitted before signing

The existing verifier accepts any structurally valid RSA public key supplied alongside the signature. That is sufficient for generic cryptographic verification, but not for a controlled owner-keyed ceremony where a preparation step must bind the expected public-key ID and fingerprint before a signature is returned.

## F-546-004 — A passing signature has no sealed, independently re-verifiable receipt

The CLI prints a verification object, but there is no deterministic receipt binding the request, exact package, exact build manifest, public key, detached signature, and truth boundary. A copied PASS can become detached from the files it described, and duplicate/replayed submissions have no stable ceremony identity.

## F-546-005 — Incomplete ceremonies lack one structured refusal boundary

Missing public key or signature inputs currently fail as ordinary command errors. A portable workflow needs a stable JSON `NOT_RUN`/`FAIL` result so operators and automation cannot confuse an unexecuted request with a completed attestation.

## F-546-006 — Legacy build-attestation fixture omitted packaged edition

The pre-0.546 unit fixture created a synthetic public package whose internal Forge manifest declared only a version. Schema-2 verification correctly treats the absent edition as development and refused the fixture's requested public edition. The fixture must declare its intended public identity rather than weakening edition verification.

## F-546-007 — Generated ceremony output was misclassified as immutable kit drift

The first extracted-kit prepare step succeeded, but subsequent finalize verification compared every file under the extracted root to the immutable payload inventory. The newly generated `ceremony/` directory therefore blocked its own valid workflow. Verification must remain exact for declared kit paths while allowing explicitly separate operator-output roots that cannot overlap immutable payload locations.

## F-546-008 — Narrative regression fixture retained pre-0.546 self-test totals

- **Observed before correction:** `tests/test_narrative_integrity.py` supplied 485 regressions and 49 modules after the attestation-kit module raised the canonical inventory to 496 regressions across 50 modules.
- **Impact:** The source-oriented narrative test failed against correct 0.546 metadata even though the production checker correctly detected the mismatch.
- **Disposition:** Update the fixture to the canonical 0.546 observed totals and retain the production mismatch refusal unchanged.
