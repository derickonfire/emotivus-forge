Complete Durable Core chunks **P1-04** ("fold overlapping release, evidence,

("replace capability activation ceremony with a minimal enabled/reason/scope/

0.554 is **sealed** on top of 0.553. Both P1-04 and P1-05 are **COMPLETE**; the

## Landed in this cycle (first fold)

Three independent investigations mapped the release, evidence/rollback/authority,
and truth-boundary clusters. They found the real overlap was **duplicated
deterministic plumbing**, not duplicated service logic: four evidence modules each
carried byte-identical copies of the archive/hash primitives and bypassed the
shared `core/common.py` entirely, and three release modules each re-implemented the
same identity read.

The safe, behavior-preserving consolidation was landed:

- Centralized the archive/hash primitives in `core/common.py`: `sha256_bytes`,
  `canonical_bytes`, `pretty_bytes`, `safe_member`, `member_is_symlink`,
  `zip_info`, and `ZIP_TIMESTAMP` (alongside the existing `sha256_file`).
- Routed `evidence_kit`, `attestation_kit`, `external_evidence`, and
  `browser_evidence` through them (bare names preserved as re-exports where tests
  import them, so behavior and every content digest are unchanged).
- Added `project_identity.current_build_id` — the truth-boundary identity read —
  and routed `release_package`, `release_proof`, and `release_distribution`
  through it instead of three private copies.
- Routed four more standalone digest helpers (`artifact_collision`,
  `build_attestation`, `narrative_integrity`, `workspace_integrity`) to
  `common.sha256_file`.

Net: ~94 lines removed across 13 modules; every extracted function is pure and
byte-identical to what it replaced, so all 523 regressions across 54 modules stay
green and no module became unreachable. Because the fold routes through existing
modules, the runtime inventory stays at 88 with zero unreachable and zero
unclassified.

## Second fold — kit-archive hygiene (P1-04 completion)

A follow-up investigation confirmed one more provably-safe fold: the archive-
hygiene block in `verify_portable_evidence_kit` and `verify_owner_attestation_kit`
was byte-identical. It was extracted into `common.verify_archive_hygiene(archive,
problems) -> (names, root_name, manifest_name, manifest)` and both verifiers
routed through it, preserving every emitted problem string and leaving each
module's distinct schema / payload / `kit_id` tail untouched (~27 lines removed).

## Distinct-by-design (evaluated, correctly not merged)

The remaining service-level "overlap" was investigated and judged genuinely
distinct, not redundant — merging it would risk evidence identity, the one
invariant P1-04 forbids:

- The receipt evaluators (`_review_receipt` / `_receipt_evaluation` /
  `_channel_receipt`) diverge on failure model (early-return vs accumulate),
  reason cardinality (singular vs plural), missing-file handling, and JSON-read
  path — a shared skeleton would raise complexity and risk asserted strings.
- The kit verifiers' `kit_id`/schema logic is distinct by construction.
- `remote_release` vs `runtime_proof` HTTP machinery differ in scheme policy and
  exception types (merging would change behavior).

P1-04 is therefore complete: everything that truly overlapped (plumbing +
hygiene) is folded; what remained is distinct-by-design.

## P1-05 — capability-activation ceremony reduction

The activation contract's over-specified attestations were removed:
`focused_regressions`, `native_advantage`, and `allow_repairs` are no longer
required, and `authority`/`scope` became optional. Every enforced safety gate was
preserved verbatim — activatable-only activation, path/evidence containment,
budget range caps, the runtime-proof egress allowlist and per-recipe binding, and
the fingerprint drift → reactivation-required lifecycle. The no-repair /
no-credential guarantee is structural in the `doctor` and `runtime_proof` services
(hard-coded), never a contract field, so dropping `allow_repairs` weakened
nothing. A genuinely minimal contract (identity + trigger + budget only) now
activates, and an out-of-range budget is still rejected.

## Boundary preserved

Forge still supplies verified context and continuity; the model owns reasoning and
implementation. No `NOT_RUN` was upgraded to `PASS`; release authorization remains
`false`.
