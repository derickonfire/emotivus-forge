# Forge 0.554 objective

Advance Durable Core chunk **P1-04** — "fold overlapping release, evidence,
rollback, and authority services into the project-truth boundary" — by removing
genuinely-duplicated code, without deleting modules (that is P1-06) and without
changing any observable behavior or evidence identity.

0.554 is in development on top of the sealed 0.553 base. It is not yet a sealed
release; P1-04 remains **ACTIVE** until the fold is complete enough that P1-06 can
remove fold-orphaned modules.

## Landed in this cycle (first fold)

Three independent investigations mapped the release, evidence/rollback/authority,
and truth-boundary clusters. They found the real overlap was **duplicated
deterministic plumbing**, not duplicated service logic: four evidence modules each
carried byte-identical copies of the archive/hash primitives and bypassed the
shared `core/common.py` entirely, and three release modules each re-implemented the
same identity read.

The safe, behavior-preserving consolidation was landed:

- Centralized the archive/hash primitives in `core/common.py`: `sha256_bytes`,
  `canonical_bytes`, `pretty_bytes`, `safe_member`, `member_is_symlink`,
  `zip_info`, and `ZIP_TIMESTAMP` (alongside the existing `sha256_file`).
- Routed `evidence_kit`, `attestation_kit`, `external_evidence`, and
  `browser_evidence` through them (bare names preserved as re-exports where tests
  import them, so behavior and every content digest are unchanged).
- Added `project_identity.current_build_id` — the truth-boundary identity read —
  and routed `release_package`, `release_proof`, and `release_distribution`
  through it instead of three private copies.
- Routed four more standalone digest helpers (`artifact_collision`,
  `build_attestation`, `narrative_integrity`, `workspace_integrity`) to
  `common.sha256_file`.

Net: ~94 lines removed across 13 modules; every extracted function is pure and
byte-identical to what it replaced, so all 523 regressions across 54 modules stay
green and no module became unreachable. Because the fold routes through existing
modules, the runtime inventory stays at 88 with zero unreachable and zero
unclassified.

## Deliberately deferred (out of scope, unsafe without deep review)

All three investigations flagged the same higher-risk merges, which 0.554 does
**not** attempt because they could silently change evidence identity — the one
invariant P1-04 forbids:

- Merging the parallel kit verifiers (`verify_portable_evidence_kit` ↔
  `verify_owner_attestation_kit`) and the archive-identity readers.
- Unifying the receipt evaluators (`_review_receipt` / `_receipt_evaluation` /
  `_channel_receipt`) — they emit distinct FAIL strings tests assert on.
- Merging `remote_release` and `runtime_proof` HTTP/origin/redirect machinery —
  different scheme policy and exception types (a behavior change, not a fold).
- The codebase-wide `hashlib.sha256(path.read_bytes())` source-fingerprint idiom.

## Remaining for P1-04 completion

The rollback (`state_transitions`, `lifecycle`) and authority
(`authority_baseline`, `authority_registry`) services already route through the
shared boundary correctly and did not bypass it. What remains before P1-04 can be
marked COMPLETE is a deeply-reviewed pass on the deferred service-level merges
above, each with an explicit evidence-identity preservation proof — the point at
which P1-06 can then remove fold-orphaned code.

## Boundary preserved

Forge still supplies verified context and continuity; the model owns reasoning and
implementation. No `NOT_RUN` was upgraded to `PASS`; release authorization remains
`false`.
